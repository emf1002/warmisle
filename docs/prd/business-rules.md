# 暖屿 V1 — 跨模块业务规则

> 本文档为跨模块共享的业务规则、非功能需求和风险评估。**任何代码修改都应查阅对应规则**。
>
> 各模块详细需求见 [modules/](modules/) 目录。

---

## 删除策略

**功能描述**：管理跨模块删除时的数据一致性保护。V1 所有删除操作统一采用软删除（逻辑删除），确保数据可追溯。

**核心规则**：

| 操作 | 条件 | 策略 | 用户感知 |
|------|------|------|----------|
| 删除成员 | 有活动记录（在任何模块中产生过数据关联） | **拒绝删除，仅可禁用** | "该成员存在活动记录，无法删除，只能禁用" |
| 删除成员 | 无活动记录 | 软删除+停用账号 | 成员从列表消失 |
| 删除分类 | 有未删除的记账记录 | **拒绝** | "该分类下存在 N 条记账记录，无法删除" |
| 删除分类 | 无记账记录 | 软删除 | 分类从列表消失 |
| 删除标签 | 有未删除的关联话题 | **拒绝** | "该标签下存在 N 条话题，无法删除" |
| 删除标签 | 无关联话题 | 软删除 | 标签从列表消失 |
| 删除记账记录 | — | 软删除 | 记录从列表消失，统计同步更新 |
| 删除待办 | — | 软删除 | 待办从列表消失，删除前二次确认 |
| 删除愿望 | — | 软删除 | 愿望及关联投票、评论同步软删除 |
| 删除动态/话题 | — | 软删除 | 内容及关联评论同步软删除 |
| 删除评论 | — | 软删除 | 评论从列表消失 |

> **设计决策**：
> 1. 判断"有关联记账记录"时，仅统计未软删除的记账记录（deleted_at IS NULL）。
> 2. V1 所有删除统一为软删除，不使用硬删除，确保数据可追溯和恢复能力。
> 3. 成员禁用规则：
>    - 有活动记录的成员只能禁用，不能删除
>    - 活动记录定义：成员在任何模块（记账/待办/愿望/评论/动态/话题/投票）中产生过数据关联
>    - 禁用后：无法登录、所有关联数据正常保留和显示、其他成员可继续操作其数据
>    - 禁用成员在列表中显示"已禁用"标签
>    - 管理员可重新启用被禁用的成员
>    - 禁止管理员禁用自己

## 空状态展示规则

**功能描述**：各模块无数据时的展示和引导规范。

**各模块空状态**：

| 模块 | 空状态场景 | 展示内容 | 引导动作 |
|------|-----------|----------|----------|
| 仪表盘 | 无收支数据 | 收入/支出/结余三张卡片均显示 ¥0.00 | 无（靠记账数据自然填充） |
| 仪表盘 | 饼图无支出数据 | 灰色占位圆 + 文案"暂无支出数据" | 无 |
| 记账本 | 当月无记录 | 居中图标 + "本月还没有记录，记一笔吧" | 显示「记一笔」按钮 |
| 记账本 | 筛选无结果 | "没有找到符合条件的记录" | 显示「清除筛选」链接 |
| 待办管理 | 无待办 | 居中图标 + "暂无待办，添加一个吧" | 显示「添加待办」按钮 |
| 待办管理 | 无已完成 | "还没有完成的事项" | 无 |
| 愿望清单 | 无个人愿望 | "还没有愿望，许一个吧" | 显示「添加愿望」按钮 |
| 愿望清单 | 无家庭愿望 | "家庭愿望池是空的，从个人愿望提升或直接创建" | 无 |
| 论坛 | 无动态/话题 | "还没有内容，发条动态或话题吧" | 显示「发动态」「发话题」按钮 |
| 论坛 | 无公告 | 不展示公告区域（直接隐藏，不留空位） | 无 |

**通用原则**：

1. 空状态必须有引导动作——不能只说"暂无数据"，要给用户下一步操作入口
2. 筛选无结果不同于无数据——筛选无结果不给创建按钮，给清除筛选链接
3. 仪表盘数字为 0 不是空状态——¥0.00 是正常数据，只有图表区域才需要占位
4. 公告区无内容直接隐藏——不占空间，比空着更干净

## 8.1 权限规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-P01 | 系统存在两种角色：admin（管理员）和 member（普通成员） |
| BR-P02 | 管理员至少一个，首次初始化时创建；管理员可将其他成员提升为管理员，也可将其他管理员降级为普通成员；禁止删除/禁用最后一个管理员 |
| BR-P03 | 管理员独占操作：管理成员（增删改、重置密码）、管理分类（增删改）、管理论坛标签（增删改）、删除他人数据、发布公告、删除他人投票、变更任何愿望的任何状态 |
| BR-P04 | 成员可操作：创建/编辑/删除自己的内容（记账、待办、愿望、动态、评论）、修改自己的姓名和头像、将自己愿望标记为"已放弃" |
| BR-P05 | 成员可查看：所有家庭数据（记账、待办、愿望、论坛），无查看权限差异 |
| BR-P06 | 成员不可操作：管理成员、管理分类、管理论坛标签、删除他人内容、发布公告 |
| BR-P07 | 个人信息页面所有角色均可访问，但只能修改自己的姓名和头像，不可修改角色和用户名 |
| BR-P08 | 管理员可禁用/启用成员；有活动记录的成员只能禁用不能删除；禁止管理员禁用自己 |
| BR-P09 | 成员禁用后无法登录，所有关联数据正常保留和显示，其他成员可继续操作其数据 |

## 8.2 认证规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-A01 | 用户名 3-20 字符，仅字母数字下划线，需唯一（创建时实时校验）；密码 6-32 字符，至少包含字母和数字 |
| BR-A02 | 登录成功后签发 Token，有效期 7 天，V1 不做 refresh token，过期后重新登录 |
| BR-A03 | 所有 API 请求需携带 Token（除登录接口外） |
| BR-A04 | Token 过期或无效返回 40101，前端跳转登录页 |
| BR-A05 | 管理员可重置成员密码，重置后密码为 `home123` |
| BR-A06 | 成员登录后若使用默认密码，强制提示修改 |
| BR-A07 | 修改密码成功后，当前 Token 立即失效，需重新登录 |
| BR-A08 | Token 使用 JWT，前端存储于 localStorage；同一账号允许多地登录 |

## 8.6 删除规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-DL01 | V1 所有删除操作统一采用软删除（设置 deleted_at 字段，查询时自动过滤） |
| BR-DL02 | 有记账引用（未删除记录）的分类不可删除；有关联话题（未删除）的标签不可删除；有活动记录的成员不可删除（只能禁用）；最后一个管理员不可删除/禁用 |
| BR-DL03 | 成员删除时，关联待办 member_id 置 NULL |
| BR-DL04 | 成员删除时，关联账号同步停用 |
| BR-DL05 | 论坛内容删除策略：自己的内容可删，管理员可删任意 |
| BR-DL06 | 愿望删除：创建者可删自己的愿望，管理员可删任意；关联投票和评论同步软删除 |
| BR-DL07 | 待办变更日志：编辑待办时记录变更内容（字段、旧值、新值、操作者、时间） |
| BR-DL08 | 所有统计查询（仪表盘收支概览、分类占比等）仅统计未软删除的记录 |
| BR-DL09 | 成员禁用规则：有活动记录（在任何模块中产生过数据关联）的成员只能禁用；禁用后无法登录、数据保留、可重新启用；禁止管理员禁用自己 |

## 8.7 并发规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-CC01 | V1 采用 Last Write Wins（最后写入胜出）策略，不引入乐观锁 |
| BR-CC02 | SQLite WAL 模式保证写事务串行化，不会出现数据损坏 |
| BR-CC03 | 写入失败时返回通用错误提示"操作失败，请重试" |
| BR-CC04 | V2 预留：如需乐观锁，加 version 字段即可 |

## 8.8 评论规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-CM01 | 评论最多2层嵌套：一级评论（直接评论内容）+ 二级评论（回复一级评论） |
| BR-CM02 | 不允许对二级评论再回复（前端隐藏回复按钮） |

| BR-CM05 | 评论系统为通用组件，愿望和论坛共用同一套评论数据模型和嵌套规则；评论删除规则统一：创建者可删除自己的评论，管理员可删除任何人的评论 |

## 8.13 备份规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-BK01 | 网盘备份功能仅管理员可操作，普通成员无法访问备份相关页面和 API |
| BR-BK02 | 阿里云盘 OAuth2 采用 Authorization Code 模式，需要的 scope：user:base、file:all:read、file:all:write |
| BR-BK03 | access_token 和 refresh_token 加密存储（AES-256-GCM），加密密钥从环境变量 BACKUP_ENCRYPTION_KEY 读取，未配置则使用内置默认密钥 |
| BR-BK04 | 备份文件上传到阿里云盘指定目录（默认 /warmisle-backups/），管理员可在设置中修改目录路径 |
| BR-BK05 | 备份文件命名格式：`warmisle_backup_YYYYMMDD_HHmmss.db`（UTC 时间） |
| BR-BK06 | 备份前必须对 SQLite 副本执行 `PRAGMA integrity_check`，检查不通过则中止备份并记录错误 |
| BR-BK07 | 备份保留策略：按天数保留（默认 30 天），定时任务执行后或手动备份成功后自动清理超过保留天数的备份文件 |
| BR-BK08 | 恢复备份前自动创建当前数据库的紧急备份（命名格式：`warmisle_pre_restore_YYYYMMDD_HHmmss.db`），确保可回退 |
| BR-BK09 | 恢复备份后服务必须自动重启，加载新数据库 |
| BR-BK10 | 恢复备份需二次确认，确认按钮文字为"我已了解风险，确认恢复"（非简单"确定"），防止误操作 |
| BR-BK11 | 备份文件下载后需校验文件大小（与云盘记录对比），不一致则拒绝替换数据库 |
| BR-BK12 | Token 刷新采用主动检查策略：每次 API 调用前检查 access_token 是否即将过期（提前 5 分钟刷新） |
| BR-BK13 | 网盘接口采用插件化设计：定义标准接口（Upload/Download/List/Delete），阿里云盘作为第一个实现 |
| BR-BK14 | 定时备份任务在配置的时间点执行一次，不支持多次/天的 cron 表达式（V1 简化设计） |
| BR-BK15 | 备份历史记录持久化到本地数据库，包含：备份时间、文件大小（字节）、云端文件 ID、状态（success/failed/in_progress）、失败原因（可选） |
| BR-BK16 | 备份失败不阻塞系统正常运行，仅记录错误日志和备份历史状态 |
| BR-BK17 | 预恢复备份（BR-BK08）文件不参与保留天数清理策略，需手动删除 |
| BR-BK18 | 阿里云盘 API 域名：`https://openapi.alipan.com`；Go SDK 参考：`github.com/tickstep/aliyunpan-api` |

## 非功能需求

| 类别 | 需求 | 指标 |
|------|------|------|
| **性能** | 列表查询响应时间 | ≤ 200ms（1万条内） |
| **性能** | 仪表盘聚合查询 | ≤ 500ms（1万条内） |
| **部署** | 启动方式 | 单二进制 + SQLite 文件，`./warmisle` 一键启动 |
| **部署** | 前端构建产物嵌入后端 | 编译后只有一个可执行文件 |
| **兼容** | 浏览器支持 | Chrome 90+、Safari 14+、Firefox 90+ |
| **兼容** | 移动端 | iOS Safari、Android Chrome |
| **可用** | 数据备份 | 支持手动备份和恢复，详见技术方案 |
| **可用** | 网盘备份 | 支持手动/定时备份到阿里云盘，支持从网盘恢复 |
| **安全** | Token 加密存储 | 阿里云盘 access_token/refresh_token 使用 AES-256-GCM 加密存储 |
| **安全** | 认证 | Token 认证，密码 bcrypt 加盐存储 |
| **安全** | 防暴力破解 | 登录失败5次锁定15分钟 |
| **安全** | 密码复杂度 | 至少包含字母和数字，6-32 字符 |
| **安全** | JWT Secret | 启动时自动生成随机 Secret，可通过环境变量配置 |
| **安全** | CORS 白名单 | 通过环境变量配置允许的 Origin 列表，默认仅允许同源 |
| **安全** | CORS | 限制白名单 Origin |
| **可靠** | 数据持久化 | SQLite WAL 模式，断电不丢数据 |
| **可靠** | 管理员密码恢复 | 提供命令行工具重置管理员密码 |
| **可靠** | 数据库迁移 | 应用启动时自动执行增量迁移（基于 goose），迁移前自动备份 SQLite 文件 |
| **可靠** | 迁移失败处理 | 迁移失败停止启动，日志输出错误，手动用备份恢复 |
| **可靠** | 迁移降级 | 不支持降级迁移，只执行 Up 方向 |

## 风险评估

| 风险 | 概率 | 影响 | 级别 | 缓解措施 |
