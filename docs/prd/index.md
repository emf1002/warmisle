## 1. 背景与目标

### 1.1 业务背景

现代家庭日常涉及收支记账、待办事项、家庭决策、生活交流等琐碎信息管理，但现有方案存在明显痛点：

- **记账类 App**：功能臃肿、广告多、数据存云端不可控、隐私担忧、单人使用为主家人不参与
- **共享文档/备忘录**：缺乏结构化，无法统计、无法关联成员
- **Excel 记账**：移动端体验差，多人协作困难，无待办联动
- **微信群**：信息碎片化无法沉淀，讨论没结论，愿望说过就忘
- **Firefly III 等自建记账**：面向个人，复式记账门槛高，无中文家庭场景适配

家庭需要一个**全员协作、私有化、全终端**的一站式数字管理中心。

### 1.2 产品目标（SMART）

| 目标 | 衡量方式 | 目标值 |
|------|----------|--------|
| 协作闭环 | 认证 + 多模块协作可用 | 全家每个人都能独立操作 |
| 私有化部署 | 单二进制 + SQLite | 一条命令启动 |
| 响应速度 | 列表查询响应时间 | ≤ 200ms（1万条内） |
| 移动端可用 | 手机浏览器可正常操作 | 核心页面 100% 适配 |
| 全员参与 | 家庭成员独立登录使用 | ≥2 人持续使用 |

### 1.3 产品定位

> **面向家庭的协作式私有数字中心**
>
> 一句话：全家人的记账、待办、愿望、交流，一个地方搞定。

### 1.4 核心定位变化

| 维度 | 旧定位 | 新定位 |
|------|--------|--------|
| 产品性质 | 记账工具+待办 | 家庭协作平台 |
| 参与模式 | 一人主记，其他人家看 | 全员协作，角色分工 |
| 核心关系 | 主从（记账人→成员） | 平权协作（管理员/成员） |
| 功能重心 | 记账为主，待办为辅 | 记账/待办/愿望/论坛并重 |
| 认证 | 无 | 角色权限体系 |

## 2. 用户分析

### 2.1 用户角色矩阵

| 角色 | 典型画像 | 核心诉求 | 核心痛点 |
|------|----------|----------|----------|
| **管理员** | 家庭的"数字大管家"，通常是技术意识强的一方 | 统一管理家庭数据和成员，确保有序 | 现有工具无法管控成员权限，数据散乱 |
| **普通成员** | 其他家庭成员（配偶、孩子等） | 参与家庭事务，了解财务和待办，表达愿望 | 不知道家庭开销全貌，想参与但没渠道 |
| **访客（V2 预留）** | 临时来访的亲戚朋友 | 查看公开内容 | 不需要账号，只看不动手 |

### 2.2 用户画像

**画像 1：张女士 — 家庭管理员**

- 年龄：35岁，职场妈妈
- 行为：管理家庭收支，安排家务分工，关注孩子愿望，发起家庭讨论
- 痛点：用过随手记，只有自己记，家人不参与；待办散落在各处，没人跟进
- 期望：一个全家人都能用的平台，自己管数据，家人各自参与

**画像 2：李先生 — 普通成员（配偶）**

- 年龄：38岁，技术爸爸
- 行为：偶尔记账，关注家庭待办，有自己的愿望想表达
- 痛点：老婆口头的"你去交电费"老忘；想买的东西说了没人重视
- 期望：有自己的账号，能看到家庭全貌，也能独立操作

**画像 3：小李 — 普通成员（孩子）**

- 年龄：12岁，初中生
- 行为：想买的东西记在愿望清单，偶尔看看家庭动态
- 痛点：想要什么只能跟爸妈说，经常被忘；想参与家庭决策但没渠道
- 期望：有自己的空间，能提愿望，能看到家庭动态

### 2.3 JTBD 需求三层分析

| 需求层级 | 记账场景 | 待办场景 | 愿望场景 | 论坛场景 |
|----------|----------|----------|----------|----------|
| **功能性** | 各自记账，汇总查看 | 创建/指派/完成待办 | 提出愿望，投票优先级 | 发帖、评论、投票 |
| **社交性** | "我也有参与家庭理财" | "事情有人负责，我来认领" | "我的需求被家人看见" | "家庭有讨论空间" |
| **情感性** | 消除"钱花哪了"的焦虑 | 消除"又忘了"的愧疚 | 满足"被重视"的期待 | 获得"我们是一家人"的归属感 |

| 消息推送/通知 | V2 考虑 |
| 拖拽排序 | V1 用数字排序 |

| 访客模式 | V2 预留 |
| 图表复杂可视化 | V1 饼图+基础图表 |
| 移动 App | V1 移动端浏览器 |
| 深色模式 | V2 考虑 |
| 第三方登录 | V1 用户名+密码 |
| 搜索功能 | V2 考虑，V1 依赖筛选 |

| 百度网盘/OneDrive 等 | V1 仅支持阿里云盘，其他网盘 V2 考虑 |

### 3.3 MVP 边界（MoSCoW）

- **Must（必须有）**：认证权限、成员管理、分类管理、记账 CRUD+筛选、待办 CRUD+指派、愿望清单、家庭论坛、仪表盘、预置数据、阿里云盘 OAuth2 授权配置、手动触发备份、定时自动备份、网盘备份文件列表查看、从网盘恢复备份
- **Should（应该有）**：记账按日期分组+日小计、记账记录者显示、月度收支小计、支出分类饼图、论坛投票、论坛点赞、愿望投票、移动端响应式、备份历史记录、备份前数据库完整性检查、备份文件加密
- **Could（可以有）**：过期待办红色高亮、仪表盘点击跳转、愿望状态流转（待讨论→已同意→已实现）、备份到多个云盘账号、其他网盘支持（百度网盘、OneDrive）、备份文件压缩
- **Won't（本次不做）**：多家庭、预算、导出、推送、访客、第三方登录、搜索、增量备份、多网盘同时备份

## 4. 价值主张

| 维度 | 内容 |
|------|------|
| **现状（Before）** | 记账靠 App（广告多/隐私差/家人不参与）；待办靠嘴说（经常忘）；愿望靠提（没人记）；家庭讨论散落在微信群（无法沉淀） |
| **解决方案（How）** | 私有化部署的家庭协作平台：认证+记账+待办+愿望+论坛，全员参与，角色分工 |
| **改变后（After）** | 每个人都有自己的账号，记账各自记汇总看，待办有人认领不遗漏，愿望被看见能投票，家庭讨论有据可查，数据在自己服务器上 |
| **替代方案** | 随手记/挖财（重+隐私差+无协作）、Firefly III（纯记账+无中文家庭场景）、Excel（体验差+无协作）、微信群（零结构化）、iOS 备忘录（无关联） |

## 13. 实施优先级（RICE）

| 需求模块 | Reach | Impact | Confidence | Effort | RICE 得分 | 排序 |
|----------|-------|--------|------------|--------|-----------|------|
| 认证与权限 | 10 | 3 | 90% | 2 | 13.5 | 1 |
| 成员管理 | 10 | 2 | 95% | 1 | 19.0 | 2 |
| 分类管理(含预置) | 10 | 2 | 95% | 1 | 19.0 | 3 |
| 记账本 CRUD+筛选 | 10 | 3 | 90% | 2 | 13.5 | 4 |
| 待办管理(含指派) | 8 | 2 | 85% | 1.5 | 9.1 | 5 |
| 仪表盘概览 | 8 | 2 | 80% | 1.5 | 8.5 | 6 |
| 愿望清单 | 7 | 2 | 75% | 2 | 5.25 | 7 |
| 家庭论坛 | 7 | 2 | 70% | 3 | 3.27 | 8 |
| 移动端响应式 | 6 | 1.5 | 75% | 1 | 6.75 | — |
| 网盘备份 | 8 | 2.5 | 80% | 2 | 8.0 | 9 |

> RICE = (Reach × Impact × Confidence) / Effort
>
> 移动端响应式贯穿所有模块开发，不作为独立任务排序。认证和成员管理是协作基础，排最前；论坛模块 Effort 最大排最后，但必须包含在 V1。网盘备份优先级排在愿望清单之后、家庭论坛之前。

## 12. 竞品对比

| 维度 | 随手记/挖财 | Firefly III | 微信群 | **暖屿 · WarmIsle** |
|------|-------------|-------------|--------|-----------------|
| 部署方式 | 云端 | 自托管(需Docker) | 云端 | **私有化(单二进制)** |
| 隐私性 | 低 | 高 | 低 | **高** |
| 家庭协作 | 弱(单人为主) | 弱(单人为主) | 中(无结构) | **强(角色+协作)** |
| 记账 | 强 | 强(复式记账) | 无 | **中等(够用)** |
| 待办管理 | 无 | 无 | 无 | **有(含指派)** |
| 愿望清单 | 无 | 无 | 无 | **有(含投票)** |
| 论坛/讨论 | 无 | 无 | 有(非结构化) | **有(结构化)** |
| 移动端体验 | 好(原生App) | 差(适配弱) | 好(原生) | **好(响应式)** |
| 上手难度 | 低 | 高(复式记账) | 低 | **低** |
| 中文家庭场景 | 部分适配 | 不适配 | 适配 | **原生适配** |

**核心竞争力**：私有化 + 全员协作 + 记账/待办/愿望/论坛一体 + 中文家庭场景 + 极简部署。

| Token | 认证令牌，登录成功后签发，用于后续请求身份验证 |
| 记录者 | 创建记账记录的用户 |
| 关联成员 | V1 暂不支持，仅记录创建者 |
| 愿望提升 | 将个人愿望提升为家庭愿望，进入家庭愿望池 |
| 待办变更日志 | 记录待办编辑操作的审计信息（字段、旧值、新值、操作者、时间） |
| 活动记录 | 成员在任何模块（记账/待办/愿望/评论/动态/话题/投票）中产生过的数据关联 |
| 成员禁用 | 将成员标记为不可登录状态，所有关联数据保留，可重新启用 |
| 信息流 | 论坛模块中动态和话题混合按时间倒序展示的列表 |
| OAuth2 | 阿里云盘开放平台授权协议，Authorization Code 模式，用于获取访问用户云盘的令牌 |
| access_token | 阿里云盘 API 访问令牌，短期有效（约 2 小时），用于调用云盘 API |
| refresh_token | 阿里云盘令牌刷新凭证，长期有效，用于在 access_token 过期时获取新令牌 |
| 紧急备份 | 恢复备份前自动创建的当前数据库副本，命名含 `pre_restore` 标识，确保恢复操作可回退 |
| 备份保留天数 | 阿里云盘上备份文件的保留期限配置，超过天数的备份文件自动清理 |
| 网盘接口插件化 | 定义标准网盘操作接口（Upload/Download/List/Delete），不同网盘作为独立实现插件接入 |
