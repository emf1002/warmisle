# UI 风格指南改进意见

> 基于 PRD V2.0.3 + 技术设计文档 V1.0.1 + UI 风格指南 V1.1.1 的交叉审查
> 审查视角：frontend-design 专业设计理念
> 日期：2026-05-17

---

## 一、总体评价

当前 UI 风格指南 V1.1.1 是一份**功能覆盖度高、规范性强**的文档，在 Token 体系、组件规范、交互反馈等方面做得很扎实。但从「面向家庭的协作式私有数字中心」这一产品定位出发，结合 frontend-design 的设计理念，存在以下核心问题：

| 维度 | 当前状态 | 目标状态 |
|------|----------|----------|
| 视觉个性 | 几乎完全依赖 Ant Design 默认外观 | 有辨识度的「家庭感」视觉语言 |
| 情感连接 | 文案层面有家庭化意识，视觉层面缺失 | 视觉 + 文案 + 交互三位一体的温暖感 |
| 动效体验 | 「保持简单，使用默认动画」 | 关键时刻有精心设计的动效 |
| 信息密度 | 规范了基础间距，缺少复杂场景指引 | 仪表盘等多信息页面有清晰的视觉层次 |
| 响应式 | 定义了断点，缺少中间态和过渡态 | 平滑适配各种屏幕尺寸 |

## 二、品牌视觉识别（重大缺失）

### 2.1 品牌色过于通用

**问题**：品牌色 `#1677FF` 是 Ant Design 的默认蓝色，与产品定位「家庭」「温暖」「协作」毫无关联。用户打开页面会感觉「这是一个后台管理系统」，而不是「我们家的数字中心」。

**改进建议**：

| 方向 | 推荐色值 | 色彩心理 | 适用理由 |
|------|----------|----------|----------|
| 暖橙系 | `#E8734A` / `#F0884A` | 温暖、活力、归属感 | 家庭场景最直觉的暖色，区别于企业蓝 |
| 森林绿系 | `#3D9B6F` / `#4CAF7D` | 自然、安心、成长 | 契合「家」的庇护感，绿色也与收入色协调 |
| 琥珀金系 | `#D4913B` / `#E5A84B` | 温馨、珍贵、信任 | 金色暗示「家庭财富管理」，与记账核心功能呼应 |
| 莫兰迪暖灰蓝 | `#6B8CAE` / `#7B9DBF` | 柔和、可靠、不张扬 | 保留蓝色的专业感，但降低饱和度增加温度 |

> **推荐方案**：以暖橙 `#E8734A` 为主色，搭配柔和米白 `#FAFAF8` 作为背景色（替代冷灰 `#F5F5F5`），营造「家」的温暖底色。

### 2.2 缺少品牌图形元素

**问题**：整个指南没有任何品牌图形语言——没有 Logo 规范、没有装饰性图案、没有可复用的视觉符号。

**改进建议**：

- **Logo / 应用图标**：定义一个简洁的房屋图形 + 数字元素的组合 Logo，用于侧边栏顶部、登录页、浏览器标签
- **装饰性图案**：设计 2-3 个轻量级 SVG 图案（如房屋轮廓、家庭成员剪影、收支曲线），用于空状态、登录页背景
- **品牌纹理**：可选地定义一个微妙的点阵或网格纹理，用于侧边栏或卡片背景，增加层次感

### 2.3 缺少登录页 / 初始化页设计规范

**问题**：登录页和初始化页是用户的第一印象，但 UI 指南完全没有覆盖。技术设计文档定义了 `/login` 和 `/init` 路由，PRD 定义了初始化流程（A-01），但视觉层面是空白。

**改进建议**：

```
登录页布局建议：
┌──────────────────────────────────────────┐
│                                          │
│          [Logo]                          │
│                                          │
│       家庭数字中心                        │
│    全家人的记账、待办、愿望、交流          │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │  用户名                            │  │
│  ├────────────────────────────────────┤  │
│  │  密码                              │  │
│  ├────────────────────────────────────┤  │
│  │         [ 登 录 ]                  │  │
│  └────────────────────────────────────┘  │
│                                          │
│          © 2026 家庭数字中心              │
└──────────────────────────────────────────┘
```

- 登录页居中卡片布局，最大宽度 400px
- 背景使用品牌色渐变或品牌纹理，不是纯白
- 初始化页复用相同布局，表单增加「确认密码」和「姓名」字段
- 移动端登录页全屏展示，无多余装饰

## 三、色彩体系改进

### 3.1 背景色缺少温度

**问题**：页面背景 `#F5F5F5` 是冷灰色，与「温暖友好」的设计原则矛盾。

**改进建议**：

| Token | 当前值 | 建议值 | 说明 |
|-------|--------|--------|------|
| colorBgLayout | `#F5F5F5` | `#FAF9F7` | 暖白底色，带一丝米色温度 |
| colorBgContainer | `#FFFFFF` | `#FFFFFF` | 保持纯白，与暖底形成层次 |
| colorBgSidebar | 未定义 | `#2C3E50` 或品牌深色 | 侧边栏需要独立背景色定义 |

### 3.2 收支色彩对比度不足

**问题**：收入绿 `#52C41A` 和支出红 `#FF4D4F` 在浅色背景上对比度尚可，但在 `#F5F5F5` 灰色背景上（如日期分组标头），小号文字可读性下降。

**改进建议**：

- 收入色加深为 `#389E0D`（Ant Design green-7），确保 12px 小号金额在灰色背景上清晰可读
- 支出色保持 `#FF4D4F`，但确保文字字重不低于 500
- 增加一条规则：**金额文字永远不低于 500 字重**，无论在什么背景上

### 3.3 缺少语义色扩展

**问题**：当前只有 4 个语义色（成功/警告/危险/信息），但 PRD 中有更多状态需要视觉区分。

**改进建议**：

| 新 Token | 建议值 | 用途 |
|----------|--------|------|
| colorInfoLight | `#E6F4FF` | 信息标签背景、选中态背景 |
| colorSuccessLight | `#F6FFED` | 已完成待办背景、收入金额背景 |
| colorWarningLight | `#FFFBE6` | 过期预警背景 |
| colorDangerLight | `#FFF2F0` | 紧急待办背景、支出金额背景 |
| colorMuted | `#8C8C8C` | 已禁用成员、次要操作 |

## 四、字体与排版改进

### 4.1 字体栈过于保守

**问题**：`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` 是最安全的系统字体栈，但完全没有个性。对于一个定位「家庭」的产品，字体应该传达温暖和亲和力。

**改进建议**：

```css
/* 推荐方案：中文优先的字体栈 */
--font-family: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", -apple-system, sans-serif;

/* 如果愿意引入 Web Font（通过 Google Fonts 或自托管） */
--font-family-display: "Noto Sans SC", sans-serif;  /* 标题用 */
--font-family-body: "Noto Sans SC", sans-serif;     /* 正文用 */
```

> **注意**：考虑到产品是单二进制部署（无外部 CDN），Web Font 需要嵌入前端产物。V1 建议使用系统字体栈，但选择更偏中文优化的排列顺序。

### 4.2 缺少数字专用字体

**问题**：金额是核心信息，但使用通用字体显示数字，表格中对齐和可读性不够好。

**改进建议**：

- 金额数字使用 `font-variant-numeric: tabular-nums`，确保等宽数字对齐
- 仪表盘大号金额可考虑使用 `font-feature-settings: "tnum"` 确保数字等宽
- 在 CSS 中定义：`.amount { font-variant-numeric: tabular-nums; letter-spacing: -0.02em; }`

### 4.3 行高规范缺失

**问题**：指南定义了字号和字重，但没有定义行高。不同场景下行高需求差异很大。

**改进建议**：

| 场景 | 行高 | 说明 |
|------|------|------|
| 页面标题 | 1.3 | 紧凑，大字号不需要大行高 |
| 卡片标题 | 1.4 | 略松，提高可读性 |
| 正文 | 1.6 | 标准阅读行高 |
| 列表项 | 1.5 | 稍紧凑，适合信息扫描 |
| 金额展示 | 1.2 | 最紧凑，数字本身有足够高度 |

## 五、布局与间距改进

### 5.1 仪表盘布局缺少规范

**问题**：仪表盘是最高频页面（D-01 到 D-05），包含收支概览、饼图、待办、愿望动态、论坛热点 5 个模块。但 UI 指南完全没有定义仪表盘的布局网格。

**改进建议**：

```
桌面端仪表盘布局（>= 768px）：
┌────────────────────────────────────────────────────────┐
│  [收入卡片]    [支出卡片]    [结余卡片]    ← 三列等宽    │
├──────────────────────────────┬─────────────────────────┤
│                              │                         │
│     支出分类饼图              │    近期待办（5条）       │
│     (占 2/3 宽度)            │    (占 1/3 宽度)        │
│                              │                         │
├──────────────────────────────┴─────────────────────────┤
│  [愿望动态（5条）]              [论坛热点]              │
│  (占 1/2 宽度)                 (占 1/2 宽度)           │
└────────────────────────────────────────────────────────┘
```

```
移动端仪表盘布局（< 768px）：
┌──────────────────────────────┐
│  [收入]  [支出]  [结余]      │  ← 三列等宽，金额竖排
├──────────────────────────────┤
│  支出分类饼图（全宽）         │
├──────────────────────────────┤
│  近期待办（5条）             │
├──────────────────────────────┤
│  愿望动态（5条）             │
├──────────────────────────────┤
│  论坛热点                    │
└──────────────────────────────┘
```

- 桌面端使用 CSS Grid：`grid-template-columns: repeat(3, 1fr)` 用于顶部卡片，`2fr 1fr` 用于中部
- 移动端单列堆叠，收支概览三卡片横向等分

### 5.2 侧边栏缺少折叠/展开状态

**问题**：技术设计文档只定义了 220px 固定宽度侧边栏。在中等屏幕（768px-1024px）上，220px 侧边栏会压缩主内容区。

**改进建议**：

| 断点 | 侧边栏状态 | 宽度 |
|------|-----------|------|
| >= 1024px | 始终展开 | 220px |
| 768px - 1023px | 默认折叠，hover 展开 | 64px / 220px |
| < 768px | 隐藏，底部 TabBar | 0 |

- 折叠态只显示图标，hover 时浮出完整菜单
- 增加 `colorBgSidebar` Token 定义侧边栏背景色

### 5.3 缺少平板适配指引

**问题**：只有移动端（< 768px）和桌面端（>= 768px）两个断点。768px-1024px 的平板/小笔记本完全没有指引。

**改进建议**：

增加中间断点 `md: 768px - 1023px`：
- 侧边栏折叠为图标模式
- 仪表盘从三列变为两列
- 表格/列表保持两列布局但间距缩小

**改进建议**：

- 月份文字居中，16px / 600
- 不限制切换范围（PRD BR-D05），但到达最早/最晚数据时箭头变灰
- 移动端可考虑使用底部 Sheet 选择器替代（更友好的月份选择体验）

### 6.5 筛选栏缺少设计

**问题**：记账本（L-03）支持按成员/分类/记录者组合筛选，待办（T-04）支持按状态/成员筛选，愿望（W-05）支持按归属/状态/创建者筛选。但筛选栏的 UI 完全没有规范。

**改进建议**：

- **桌面端**：水平排列的筛选条件，使用 Ant Design Select 组件，筛选栏与列表之间有 8px 间距
- **移动端**：筛选条件折叠为「筛选」按钮，点击弹出底部 Sheet（Drawer from bottom），避免占用列表空间
- 筛选激活时，筛选按钮显示激活态（品牌色边框或小圆点指示）
- 「清除筛选」按钮紧随筛选条件之后

## 七、动效与过渡（重大改进）

### 7.1 当前策略过于保守

**问题**：第 5 节「过渡与动画」只有 4 行，全部是「使用 Ant Design 默认」「无自定义动画」「保持简单」。对于一个面向家庭的产品，适当的动效是建立情感连接的关键手段。

**改进建议**：

| 场景 | 建议动效 | 实现方式 | 理由 |
|------|----------|----------|------|
| 待办勾选完成 | 文字加删除线 + 淡出移至底部 | CSS transition + Vue `<TransitionGroup>` | 给用户「搞定一件事」的满足感 |
| 点赞切换 | 心形图标 scale 弹跳（1→1.3→1） | CSS `@keyframes` 150ms | 社交产品的标准愉悦反馈 |
| 金额数字变化 | 数字滚动/淡入淡出 | CSS transition on opacity | 仪表盘切换月份时数据变化不突兀 |
| 页面切换 | 淡入（150ms ease-out） | Vue `<Transition>` | 比瞬间切换更柔和，但不拖沓 |
| 卡片出现 | 从下方滑入 + 淡入（stagger 50ms） | CSS animation + `animation-delay` | 列表加载完成时逐个出现，有节奏感 |
| 删除确认弹窗 | 背景遮罩淡入 + 弹窗缩放弹出 | Ant Design 默认（已足够） | 保持默认即可 |
| 侧边栏折叠/展开 | 宽度 transition 200ms | CSS `transition: width` | 平滑过渡，不突兀 |

### 7.2 缺少微交互规范

**改进建议**：

- **按钮 hover**：轻微上移 1px + 阴影加深（`transform: translateY(-1px); box-shadow: ...`）
- **卡片 hover**：轻微提升 + 阴影变化（桌面端），移动端无 hover
- **列表项按下**：背景色变深一层（`active: background-color: var(--colorBgLayout)`），提供触觉反馈感
- **Tab 切换**：底部指示条滑动过渡（`transition: transform 200ms`），而非瞬间跳转

### 7.3 骨架屏需要定制

**问题**：加载状态只说了用 Ant Design `<Skeleton>`，但没有定义骨架屏的形状应该匹配实际内容。

**改进建议**：

- 记账列表骨架屏：模拟日期标头 + 3-4 条记录卡片的形状
- 仪表盘骨架屏：模拟三张概览卡片 + 饼图占位
- 论坛骨架屏：模拟 3-4 条信息流卡片的形状
- 使用 Ant Design Skeleton 的 `active` 属性，提供脉冲动画

## 八、信息层级与视觉层次

### 8.1 缺少阴影层级体系

**问题**：只定义了 2 级阴影（卡片 + 浮层），缺少中间态。

**改进建议**：

| 层级 | 阴影值 | 使用场景 |
|------|--------|----------|
| level-0 | `none` | 侧边栏、TabBar、内嵌区域 |
| level-1 | `0 1px 2px rgba(0,0,0,0.06)` | 卡片、列表项 |
| level-2 | `0 2px 8px rgba(0,0,0,0.08)` | hover 态卡片、筛选栏 |
| level-3 | `0 4px 12px rgba(0,0,0,0.12)` | 下拉菜单、弹窗 |
| level-4 | `0 8px 24px rgba(0,0,0,0.15)` | 全屏遮罩上的 Modal |

### 8.2 缺少 z-index 层级规范

**问题**：多个浮层可能同时出现（如 Modal + Tooltip + Dropdown），没有 z-index 规范会导致遮挡问题。

**改进建议**：

| 层级 | z-index | 元素 |
|------|---------|------|
| base | 0-9 | 页面内容 |
| sticky | 10-19 | 月份小计 sticky、侧边栏 |
| dropdown | 20-29 | 下拉菜单、Select、DatePicker |
| sticky-header | 30-39 | 日期分组标头 sticky |
| overlay | 40-49 | Drawer、Popover |
| modal | 50-59 | Modal、确认弹窗 |
| message | 60-69 | Toast 通知 |
| notification | 70-79 | Notification 弹窗 |

## 九、响应式设计补充

### 9.1 移动端记账表单需要专门设计

**问题**：记账表单包含分类选择、金额输入、关联成员多选、日期选择、备注输入 5 个字段。移动端满宽堆叠会导致表单过长，键盘弹出时体验差。

**改进建议**：

- **分类选择**：使用网格布局（4-5 列）展示 emoji + 名称，而非下拉选择器，减少操作步骤
- **关联成员**：使用 Chip/Tag 多选组件，横向排列，而非多选下拉
- **金额输入**：固定在表单顶部显眼位置，大字号输入
- **日期选择**：默认今天，收起在「更多选项」中
- **备注**：单行输入，收起在「更多选项」中
- 移动端表单应分为「必填区」（分类 + 金额 + 关联成员）和「可选区」（日期 + 备注），可选区默认折叠

### 9.2 移动端论坛发帖需要专门设计

**问题**：论坛有 3 种内容类型（动态/话题/投票），移动端需要清晰的入口区分。

**改进建议**：

- 使用 FAB（Floating Action Button）悬浮按钮作为发帖入口
- 点击后弹出底部 Sheet，提供 3 个选项：「发动态」「发话题」「发起投票」
- 各类型表单在 Sheet 中完成，而非跳转新页面

### 9.3 横屏适配

**问题**：完全没有横屏适配指引。手机横屏时（如 iPad mini 或手机横放），布局可能出现问题。

**改进建议**：

- V1 横屏不做特殊优化，但确保不出现内容溢出或遮挡
- 添加 `max-width: 100vw; overflow-x: hidden` 防止横向滚动
- 表格/列表在横屏时自动利用更宽的空间

## 十、无障碍与可访问性

### 10.1 完全缺失无障碍规范

**问题**：指南没有提及任何无障碍（a11y）要求。虽然 PRD 提到「考虑老人和儿童操作」，但没有落实到具体规范。

**改进建议**：

| 规则 | 说明 |
|------|------|
| 最小点击目标 | 44×44px（已有，但需扩展到所有可交互元素，包括链接） |
| 色彩对比度 | 正文文字与背景对比度 >= 4.5:1（WCAG AA），大号文字 >= 3:1 |
| 不仅靠颜色传达信息 | 收支不能只靠颜色区分，必须同时使用 +/- 符号（已有，但需强调） |
| 焦点可见 | 所有可交互元素在键盘聚焦时有可见的焦点环（`outline: 2px solid var(--colorPrimary)`） |
| 语义化 HTML | 使用 `<nav>`, `<main>`, `<article>`, `<button>` 等语义标签 |
| ARIA 标签 | emoji 头像需要 `aria-label`（如 `aria-label="张三的头像"`） |
| 键盘导航 | Tab 顺序符合视觉顺序，Modal 打开时焦点 trap |

## 十一、与 PRD / 技术设计的不一致之处

### 11.1 按钮文案规则与 PRD 矛盾

**问题**：UI 指南 3.11.2 规定「不用纯名词：不写"保存"，写"保存分类"」。但 PRD 中多处用户故事使用纯动词按钮：
- A-03：「退出登录」→ 指南要求「确认退出登录」（一致 ✓）
- P-04：「确定要退出登录吗？」→ 指南要求二次确认（一致 ✓）
- 但「保存」按钮在编辑分类、编辑成员等场景中频繁出现

**改进建议**：放宽规则，允许以下场景使用纯动词：
- 表单底部的主操作按钮可以使用纯动词（「保存」「提交」），因为上下文已经明确
- 列表/卡片上的操作按钮需要「动词+对象」（「保存分类」「添加成员」）

### 11.2 仪表盘移动端入口缺失

**问题**：PRD 定义了仪表盘的 5 个子模块（D-01 到 D-05），移动端 TabBar 有 5 个 Tab。但 UI 指南 4.0 只定义了愿望清单的移动端入口（通过仪表盘内嵌区域），没有定义分类管理和成员管理的移动端入口。

**技术设计文档已补充**：个人中心页面（`/profile`）包含分类管理和成员管理的跳转入口。但 UI 指南应明确这一点。

### 11.3 投票截止状态缺少视觉规范

**问题**：PRD 定义了投票截止后「可查看结果但不可投票」，技术设计定义了 `deadline_at` 字段。但 UI 指南 3.5 只说「截止投票：选项不可选，仅显示结果」，缺少具体的视觉表现。

**改进建议**：

- 投票截止后，选项区域增加半透明遮罩（`opacity: 0.7`）
- 投票按钮变为「已结束」灰色标签
- 截止日期显示为「已于 5月30日 截止」

## 十二、建议新增章节

### 12.1 图标规范

当前指南完全没有图标规范。建议新增：

| 维度 | 规范 |
|------|------|
| 图标库 | 使用 Ant Design Icons（与组件库一致），不混用其他图标库 |
| 图标尺寸 | 导航 20px、按钮内 16px、列表 16px、提示 24px |
| 图标颜色 | 继承父元素文字颜色，不单独设色 |
| 图标与文字间距 | 4px（紧凑）/ 8px（标准） |
| 禁止 | 不用图标代替文字标签（无障碍考虑） |

### 12.2 暗色模式预留

虽然 PRD 明确 V1 不做暗色模式，但建议在 Token 体系中预留暗色模式变量命名空间：

```css
:root {
  --color-bg-layout: #FAF9F7;
  /* ... */
}

/* V2 预留，V1 不实现 */
@media (prefers-color-scheme: dark) {
  :root {
    --color-bg-layout: #141414;
    /* ... */
  }
}
```

这样 V2 引入暗色模式时不需要重构 CSS 结构。

### 12.3 打印样式预留

记账数据可能需要打印（如月度报表），建议预留 `@media print` 基础样式：
- 隐藏侧边栏、TabBar、按钮
- 白色背景、黑色文字
- 移除阴影和圆角

## 十三、优先级排序

按实施影响和紧急程度排序：

| 优先级 | 改进项 | 理由 |
|--------|--------|------|
| 🔴 P0 | 品牌色重新定义 | 影响全局视觉基调，越早改成本越低 |
| 🔴 P0 | 登录/初始化页设计规范 | 用户第一印象，目前完全空白 |
| 🔴 P0 | 记账卡片 + 待办卡片设计规范 | 核心功能，开发前必须有设计 |
| 🟡 P1 | 仪表盘布局网格 | 最高频页面，缺少布局规范 |
| 🟡 P1 | 论坛信息流卡片设计 | 最复杂模块，4 种内容类型需要统一规范 |
| 🟡 P1 | 筛选栏 + 月份切换器设计 | 多个模块共用，需要统一 |
| 🟡 P1 | 动效规范（待办完成、点赞、列表加载） | 情感连接的关键手段 |
| 🟢 P2 | 背景色温度调整 | 提升整体温暖感 |
| 🟢 P2 | 阴影层级 + z-index 规范 | 防止后续开发中的层级混乱 |
| 🟢 P2 | 无障碍基础规范 | 合规 + 老人儿童友好 |
| 🔵 P3 | 平板适配指引 | V1 可简化处理 |
| 🔵 P3 | 暗色模式预留 | V2 再做 |
| 🔵 P3 | 图标规范 | 开发过程中逐步补充即可 |
