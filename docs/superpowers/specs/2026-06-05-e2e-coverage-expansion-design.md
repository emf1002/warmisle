# E2E 测试覆盖率全量补充设计

## 概述

当前 e2e 测试套件有 50 个用例，覆盖了各模块的基本 CRUD 和空状态。本设计目标是按 RICE 优先级逐模块补齐所有缺失场景，涵盖功能测试、权限测试、错误路径测试和移动端响应式测试四个维度。

## 当前状态

| 维度 | 现状 |
|------|------|
| 测试用例数 | 50 个，10 个 spec 文件 |
| 角色覆盖 | 仅 admin，无 member 角色测试 |
| 功能覆盖 | 基本 CRUD + 空状态，核心业务流程大量缺失 |
| 权限测试 | 零覆盖 |
| 错误路径 | 零覆盖 |
| 移动端 | 零覆盖（仅 1280x720 桌面端） |
| POM 方法利用率 | 31 个方法已定义但未被调用 |

## 设计目标

1. **功能场景补齐**：每个模块覆盖完整的 happy path + 业务规则
2. **权限与角色测试**：验证 admin/member 权限边界
3. **错误路径测试**：表单校验、API 错误、业务规则拒绝
4. **移动端响应式测试**：375px 视口下的核心页面验证

## 基础设施变更

### 1. 扩展 auth.fixture.ts — 支持 member 角色

在现有 `authenticated` fixture 基础上，新增 `memberContext` fixture：

```typescript
// 新增 fixture 类型
type AuthFixtures = {
  authenticated: {
    page: Page;
    token: string;
    seedLedgers: (options?: SeedLedgersOptions) => Promise<SeedLedgersResult>;
  };
  // 新增：member 角色的已认证上下文
  memberContext: {
    page: Page;
    token: string;
  };
};
```

**实现方式**：
- `authenticated` fixture 保持不变（admin 角色）
- 新增 `memberContext` fixture：在 `authenticated` 完成后，调用后端 API 创建一个 member 角色用户，返回独立的 page + token
- 需要新增后端测试端点 `POST /api/test/create-member`（仅 HC_TEST_MODE 下可用），快速创建 member 用户并返回 token

### 2. 新增后端测试端点

`POST /api/test/create-member` — 创建 member 角色用户，返回 token：

```json
// Request
{ "username": "member1", "password": "test123", "name": "成员一" }
// Response
{ "code": 0, "data": { "token": "..." } }
```

### 3. Playwright 配置 — 新增 mobile project

在 `playwright.config.ts` 中新增 mobile project：

```typescript
projects: [
  { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  { name: 'mobile', use: { ...devices['iPhone 13'] } },  // 390x844
]
```

移动端测试单独标记 `test.describe.configure({ tag: '@mobile' })`，可独立运行。

## 实施约束

1. **每个模块独立可验证** — 完成一个模块即可运行该模块的测试，不依赖后续模块
2. **复用现有 POM 方法** — 优先使用已定义但未调用的方法，仅在必要时新增
3. **fixture 扩展向后兼容** — 新增 `memberContext` fixture 不影响现有 `authenticated` fixture
4. **移动端标记** — 移动端用例使用 `@mobile` tag，可独立运行：`npx playwright test --grep @mobile`
5. **视觉回归基线** — 新增的视觉回归测试首次运行自动生成基线，需手动 review 后提交

## 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| member fixture 方式 | 扩展现有 auth.fixture.ts | 保持单一 fixture 文件，减少维护成本 |
| member 创建方式 | 新增后端测试端点 | 比通过 UI 创建更快速可靠 |
| 移动端实现 | Playwright project 配置 | 原生支持，无需修改测试代码 |
| 移动端设备 | iPhone 13 (390x844) | 覆盖主流移动设备尺寸 |
| 移动端测试范围 | 关键页面 + 视觉回归 | 不重复所有桌面端测试，聚焦响应式验证 |
