## 1. 背景与目标

### 1.1 业务背景

现代家庭日常涉及收支记账、待办事项、家庭决策、生活交流等琐碎信息管理，但现有方案存在明显痛点：

- **记账类 App**：功能臃肿、广告多、数据存云端不可控、隐私担忧、单人使用为主家人不参与
- **共享文档/备忘录**：缺乏结构化，无法统计、无法关联成员
- **Excel 记账**：移动端体验差，多人协作困难，无待办联动
- **微信群**：信息碎片化无法沉淀，讨论没结论，愿望说过就忘
- **Firefly III 等自建记账**：面向个人，复式记账门槛高，无中文家庭场景适配

家庭需要一个**全员协作、私有化、全终端**的一站式数字管理中心。

### 1.2 产品目标（SMART）

| 目标 | 衡量方式 | 目标值 |
|------|----------|--------|
| 协作闭环 | 认证 + 多模块协作可用 | 全家每个人都能独立操作 |
| 私有化部署 | 单二进制 + SQLite | 一条命令启动 |
| 响应速度 | 列表查询响应时间 | ≤ 200ms（1万条内） |
| 移动端可用 | 手机浏览器可正常操作 | 核心页面 100% 适配 |
| 全员参与 | 家庭成员独立登录使用 | ≥2 人持续使用 |

### 1.3 产品定位

> **面向家庭的协作式私有数字中心**
>
> 一句话：全家人的记账、待办、愿望、交流，一个地方搞定。

### 1.4 核心定位变化

| 维度 | 旧定位 | 新定位 |
|------|--------|--------|
| 产品性质 | 记账工具+待办 | 家庭协作平台 |
| 参与模式 | 一人主记，其他人家看 | 全员协作，角色分工 |
| 核心关系 | 主从（记账人→成员） | 平权协作（管理员/成员） |
| 功能重心 | 记账为主，待办为辅 | 记账/待办/愿望/论坛并重 |
| 认证 | 无 | 角色权限体系 |

## 2. 用户分析

### 2.1 用户角色矩阵

| 角色 | 典型画像 | 核心诉求 | 核心痛点 |
|------|----------|----------|----------|
| **管理员** | 家庭的"数字大管家"，通常是技术意识强的一方 | 统一管理家庭数据和成员，确保有序 | 现有工具无法管控成员权限，数据散乱 |
| **普通成员** | 其他家庭成员（配偶、孩子等） | 参与家庭事务，了解财务和待办，表达愿望 | 不知道家庭开销全貌，想参与但没渠道 |
| **访客（V2 预留）** | 临时来访的亲戚朋友 | 查看公开内容 | 不需要账号，只看不动手 |

### 2.2 用户画像

**画像 1：张女士 — 家庭管理员**

- 年龄：35岁，职场妈妈
- 行为：管理家庭收支，安排家务分工，关注孩子愿望，发起家庭讨论
- 痛点：用过随手记，只有自己记，家人不参与；待办散落在各处，没人跟进
- 期望：一个全家人都能用的平台，自己管数据，家人各自参与

**画像 2：李先生 — 普通成员（配偶）**

- 年龄：38岁，技术爸爸
- 行为：偶尔记账，关注家庭待办，有自己的愿望想表达
- 痛点：老婆口头的"你去交电费"老忘；想买的东西说了没人重视
- 期望：有自己的账号，能看到家庭全貌，也能独立操作

**画像 3：小李 — 普通成员（孩子）**

- 年龄：12岁，初中生
- 行为：想买的东西记在愿望清单，偶尔看看家庭动态
- 痛点：想要什么只能跟爸妈说，经常被忘；想参与家庭决策但没渠道
- 期望：有自己的空间，能提愿望，能看到家庭动态

## 3. 范围定义

### 3.1 包含范围（In Scope）

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 认证与权限 | 登录/登出、角色体系（管理员/成员）、身份识别 | Must |
| 成员管理 | 家庭成员增删改查、头像角色、密码管理 | Must |
| 分类管理 | 收入/支出分类管理、预置常用分类 | Must |
| 记账本 | 收支记录 CRUD、记录者+关联成员、按月/成员/分类筛选、分页 | Must |
| 待办管理 | 待办 CRUD、完成切换、优先级、截止日期、指派、认领 | Must |
| 愿望清单 | 个人愿望+家庭愿望池、优先级/预算、投票、状态流转 | Must |
| 家庭论坛 | 动态墙、话题讨论、家庭公告、投票 | Must |
| 仪表盘 | 收支概览、支出统计、近期待办、愿望动态、论坛热点 | Must |
| 响应式布局 | 桌面端侧边栏 + 移动端底栏 | Must |
| 个人中心 | 个人信息查看/编辑、修改密码、退出登录、分类/成员管理入口 | Must |

| 功能 | 原因 |
|------|------|
| 多家庭/多空间 | V1 单家庭，后续迭代 |
| 预算管理 | 非核心，V2 考虑 |
| 数据导入/导出 | V2 考虑 |
| 消息推送/通知 | V2 考虑 |
| 拖拽排序 | V1 用数字排序 |
| 灵感板/收藏夹 | V2 考虑，V1 愿望清单已覆盖核心 |
| 访客模式 | V2 预留 |
| 图表复杂可视化 | V1 饼图+基础图表 |
| 移动 App | V1 移动端浏览器 |
| 深色模式 | V2 考虑 |
| 第三方登录 | V1 用户名+密码 |
| 搜索功能 | V2 考虑，V1 依赖筛选 |
| 批量操作 | V2 考虑，V1 逐条操作 |
| 离线/弱网支持 | V2 考虑，V1 依赖网络连接 |
| 消息通知/提醒 | V1 不做任何通知机制，用户需主动查看各模块 |
| 论坛内容编辑 | V1 动态/话题发布后不支持编辑，需删除重建 |

### 3.3 MVP 边界（MoSCoW）

- **Must（必须有）**：认证权限、成员管理、分类管理、记账 CRUD+筛选、待办 CRUD+指派、愿望清单、家庭论坛、仪表盘、预置数据
- **Should（应该有）**：记账按日期分组+日小计、记账记录者显示、月度收支小计、支出分类饼图、论坛投票、论坛点赞、愿望投票、移动端响应式
- **Could（可以有）**：过期待办红色高亮、仪表盘点击跳转、愿望状态流转（待讨论→已同意→已实现）
- **Won't（本次不做）**：多家庭、预算、导出、推送、访客、第三方登录、搜索

## 4. 价值主张

| 维度 | 内容 |
|------|------|
| **现状（Before）** | 记账靠 App（广告多/隐私差/家人不参与）；待办靠嘴说（经常忘）；愿望靠提（没人记）；家庭讨论散落在微信群（无法沉淀） |
| **解决方案（How）** | 私有化部署的家庭协作平台：认证+记账+待办+愿望+论坛，全员参与，角色分工 |
| **改变后（After）** | 每个人都有自己的账号，记账各自记汇总看，待办有人认领不遗漏，愿望被看见能投票，家庭讨论有据可查，数据在自己服务器上 |
| **替代方案** | 随手记/挖财（重+隐私差+无协作）、Firefly III（纯记账+无中文家庭场景）、Excel（体验差+无协作）、微信群（零结构化）、iOS 备忘录（无关联） |

## 7. 详细功能说明

### 7.1 认证与权限模块

**功能描述**：用户登录/登出，基于角色的访问控制。

**主流程 — 初始化**：
1. 首次访问系统，检测无任何用户数据
2. 进入初始化页面，引导创建管理员账号（用户名+密码+姓名）
3. 系统创建管理员成员记录，关联账号
4. 系统自动创建预置数据：预置分类（支出15个+收入5个）、预置标签（10个）
5. 自动登录，进入仪表盘

**主流程 — 登录**：
1. 用户输入用户名+密码
2. 系统校验，签发 Token
3. 前端存储 Token，后续请求携带
4. 若使用默认密码，弹出提示"请修改密码"

**权限校验流程**：
1. 每个请求携带 Token
2. 中间件解析 Token，获取用户 ID 和角色
3. 管理员操作校验角色为 admin
4. 成员操作校验资源归属（只能编辑/删除自己的内容）

**异常流程**：

| 异常场景 | 处理策略 |
|----------|----------|
| 用户名或密码错误 | 提示"用户名或密码错误"，5次失败后锁定15分钟 |
| Token 过期 | 返回认证错误，前端跳转登录页 |
| 无 Token 访问受保护接口 | 返回认证错误 |
| 用户名已存在 | 提示"用户名已被使用"（创建时实时校验） |
| 非管理员访问管理员接口 | 返回权限不足错误，提示"权限不足" |
| 成员编辑他人资源 | 返回权限不足错误，提示"只能操作自己的内容" |
| 登录失败锁定 | 针对用户名锁定，5次失败后锁定15分钟自动解锁；管理员被锁定可通过命令行工具重置 |

### 7.2 记账本模块

**功能描述**：家庭成员记录每笔收支，支持多维度查看和筛选。协作模式下区分"记录者"和"关联成员"（多对多关系）。

**前置条件**：至少存在 1 个成员和 1 个分类。用户已登录。

**主流程**：
1. 用户点击「记一笔」按钮
2. 系统弹出记账表单，默认选中"支出"分类列表
3. 用户选择分类 → 输入金额(元) → 选择关联成员(可多选，至少选一个) → 选择日期(默认今天) → 填写备注(可选，单行输入，最大200字符)
4. 系统校验：金额 > 0、分类存在、关联成员存在
5. 系统从分类确定收支方向，记录者设为当前用户，保存记录（关联成员通过中间表存储）
6. 列表刷新，新记录出现在对应日期分组中

**异常流程**：

| 异常场景 | 处理策略 |
|----------|----------|
| 金额为 0 或负数 | 前端拦截，提示"请输入正数金额" |
| 选择的分类已删除 | 后端返回 40004，前端提示"分类不存在" |
| 选择的成员已删除 | 后端返回 40004，前端提示"成员不存在" |
| 网络中断 | 前端提示"网络错误"，数据不丢失 |

**记账列表展示规则**：
1. 按日期分组展示，日期倒序排列（最新日期在上）
2. 日期格式：今天显示"今天"，昨天显示"昨天"，更早显示"M月D日 周X"
3. 每个日期分组显示当日支出小计
4. 月度收支小计（收入/支出/结余）固定在列表顶部（sticky），结余为负红色高亮
5. 每条记录显示记录者头像+姓名，体现协作记账的归属
6. 备注在列表中截断展示（超过30字符显示省略号），点击可查看完整内容

**后置条件**：记账记录持久化，仪表盘统计数据相应更新。

### 7.3 待办管理模块

**功能描述**：创建和管理家庭待办事项，支持指派、认领、优先级、截止日期和完成切换。

**前置条件**：用户已登录。成员为可选项。

**主流程**：
1. 用户点击「添加待办」按钮
2. 填写标题(必填)、描述(可选)、指派成员(可选)、优先级(默认普通)、截止日期(可选)
3. 保存后出现在待办列表，创建者为当前用户
4. 被指派的成员可在自己的待办列表中看到
5. 未指派的待办可被其他成员认领
6. 完成时点击勾选框，状态切换为已完成，记录完成时间
7. 可再次点击恢复为待办
8. 编辑待办时，创建者和被指派人皆可编辑；系统自动记录变更日志（字段、旧值、新值、操作者、时间）

**异常流程**：

| 异常场景 | 处理策略 |
|----------|----------|
| 标题为空 | 前端拦截，提示"请输入标题" |
| 指派的成员已删除 | 后端忽略，成员字段置空 |
| 认领已被指派的待办 | 后端拒绝，提示"该待办已被指派" |

### 7.4 愿望清单模块

**功能描述**：家庭成员提出愿望，可提升为家庭愿望，支持投票和状态流转。个人愿望对所有成员可见（只读），提升后进入家庭愿望池可投票讨论。

**前置条件**：用户已登录。

**主流程**：
1. 用户点击「添加愿望」
2. 填写标题(必填)、描述(可选)、分类(物品/旅行/体验/其他)、预估金额(可选)、优先级(普通/重要/紧急，仅展示不参与排序)、归属(个人/家庭，默认个人)
3. 保存后出现在对应归属的愿望列表；个人愿望其他成员可查看（只读），家庭愿望所有成员可投票讨论
4. 个人愿望仍可「提升为家庭愿望」（单向操作，不可降回）
5. 家庭愿望出现在家庭愿望池，所有成员可投票讨论
6. 其他成员可为愿望投票
7. 管理员可变更任何愿望的任何状态：待讨论→已同意→已实现/已放弃
8. 创建者可将自有愿望标记为"已放弃"（仅此一个状态）

**愿望状态流转**：

```
创建 → 待讨论 → 已同意 → 已实现
         │                └→ 已放弃（创建者可标记）
         └→ 已放弃（创建者可标记）
```

**删除规则**：
- 创建者可删除自己的愿望（软删除，关联投票和评论同步软删除）
- 管理员可删除任何人的愿望
- 删除前二次确认

### 7.5 家庭论坛模块

**功能描述**：家庭成员交流的空间，包含动态墙、话题讨论、家庭公告和投票。

**前置条件**：用户已登录。

**内容类型**：

| 类型 | 说明 | 谁可创建 | 数据模型 |
|------|------|----------|----------|
| 动态 | 短内容，类似朋友圈 | 所有成员 | 独立类型 |
| 话题 | 结构化讨论，有标题+内容+回复，可选标签 | 所有成员 | 独立类型 |
| 公告 | 置顶通知，本质是带"公告"标签的话题 | 管理员 | 与话题共用数据模型，取消置顶后变为普通话题（可评论、可点赞） |
| 投票 | 带选项的家庭决策 | 所有成员 | 独立类型 |

**信息流展示规则**：
- 动态和话题在同一个信息流中按创建时间倒序混合展示
- 公告始终置顶在信息流顶部，按创建时间倒序排列
- 动态无标题，以卡片形式展示内容+作者+时间
- 话题有标题+标签，以卡片形式展示标题+摘要+作者+时间
- 公告带"公告"标签，视觉上与普通内容区分
- 公告在置顶期间不支持评论和点赞；管理员取消置顶后变为普通话题，可评论、可点赞
- 管理员可取消公告置顶，取消后变为普通话题
- 动态和话题发布后不支持编辑，需删除重建

**标签管理**：

| 维度 | 说明 |
|------|------|
| 管理方式 | 管理员维护（增删改），成员发话题时从列表选择 |
| 每条话题 | 可选 1 个标签 |
| 预置标签 | 家务、育儿、出行、饮食、健康、教育、财务、购物、装修、宠物 |
| 删除保护 | 有关联话题（未删除）的标签不可删除 |
| 管理入口 | 论坛模块内，管理员可见"管理标签" |

**主流程 — 发布动态**：
1. 用户在动态墙输入文字内容
2. 点击发布，动态出现在动态墙顶部
3. 其他成员可评论和点赞

**主流程 — 发起投票**：
1. 成员设置投票标题和选项（2-10个）
2. 可设单选/多选、截止时间
3. 发布后所有成员可参与投票
4. 实时显示投票结果

**投票规则**：
- 投票发布后不可编辑（已有人投票后改选项会导致数据不一致）
- 需要修改请删除后重新创建
- 截止日期精度到天，不设截止日期则永久有效
- 截止后所有成员可查看结果，但不可投票
- 投票截止后禁止删除（保留投票记录的完整性）
- 截止前：创建者和管理员可删除投票，删除时关联的投票记录和评论同步软删除

**点赞规则**：
- 可对动态、话题、评论点赞
- 再次点击取消点赞
- 公告在置顶期间不可点赞，取消置顶变为普通话题后可点赞

**异常流程**：

| 异常场景 | 处理策略 |
|----------|----------|
| 重复投票 | 后端拒绝，每人只能投一次 |
| 投票已截止 | 后端拒绝，提示"投票已结束" |
| 动态内容为空 | 前端拦截 |

### 7.6 删除策略模块

**功能描述**：管理跨模块删除时的数据一致性保护。V1 所有删除操作统一采用软删除（逻辑删除），确保数据可追溯。

**核心规则**：

| 操作 | 条件 | 策略 | 用户感知 |
|------|------|------|----------|
| 删除成员 | 有活动记录（在任何模块中产生过数据关联） | **拒绝删除，仅可禁用** | "该成员存在活动记录，无法删除，只能禁用" |
| 删除成员 | 无活动记录 | 软删除+停用账号 | 成员从列表消失 |
| 删除分类 | 有未删除的记账记录 | **拒绝** | "该分类下存在 N 条记账记录，无法删除" |
| 删除分类 | 无记账记录 | 软删除 | 分类从列表消失 |
| 删除标签 | 有未删除的关联话题 | **拒绝** | "该标签下存在 N 条话题，无法删除" |
| 删除标签 | 无关联话题 | 软删除 | 标签从列表消失 |
| 删除记账记录 | — | 软删除 | 记录从列表消失，统计同步更新 |
| 删除待办 | — | 软删除 | 待办从列表消失，删除前二次确认 |
| 删除愿望 | — | 软删除 | 愿望及关联投票、评论同步软删除 |
| 删除动态/话题 | — | 软删除 | 内容及关联评论同步软删除 |
| 删除评论 | — | 软删除 | 评论从列表消失 |

> **设计决策**：
> 1. 判断"有关联记账记录"时，仅统计未软删除的记账记录（deleted_at IS NULL）。
> 2. V1 所有删除统一为软删除，不使用硬删除，确保数据可追溯和恢复能力。
> 3. 成员禁用规则：
>    - 有活动记录的成员只能禁用，不能删除
>    - 活动记录定义：成员在任何模块（记账/待办/愿望/评论/动态/话题/投票）中产生过数据关联
>    - 禁用后：无法登录、所有关联数据正常保留和显示、其他成员可继续操作其数据
>    - 禁用成员在列表中显示"已禁用"标签
>    - 管理员可重新启用被禁用的成员
>    - 禁止管理员禁用自己

### 7.7 空状态展示规则

**功能描述**：各模块无数据时的展示和引导规范。

**各模块空状态**：

| 模块 | 空状态场景 | 展示内容 | 引导动作 |
|------|-----------|----------|----------|
| 仪表盘 | 无收支数据 | 收入/支出/结余三张卡片均显示 ¥0.00 | 无（靠记账数据自然填充） |
| 仪表盘 | 饼图无支出数据 | 灰色占位圆 + 文案"暂无支出数据" | 无 |
| 记账本 | 当月无记录 | 居中图标 + "本月还没有记录，记一笔吧" | 显示「记一笔」按钮 |
| 记账本 | 筛选无结果 | "没有找到符合条件的记录" | 显示「清除筛选」链接 |
| 待办管理 | 无待办 | 居中图标 + "暂无待办，添加一个吧" | 显示「添加待办」按钮 |
| 待办管理 | 无已完成 | "还没有完成的事项" | 无 |
| 愿望清单 | 无个人愿望 | "还没有愿望，许一个吧" | 显示「添加愿望」按钮 |
| 愿望清单 | 无家庭愿望 | "家庭愿望池是空的，从个人愿望提升或直接创建" | 无 |
| 论坛 | 无动态/话题 | "还没有内容，发条动态或话题吧" | 显示「发动态」「发话题」按钮 |
| 论坛 | 无公告 | 不展示公告区域（直接隐藏，不留空位） | 无 |

**通用原则**：

1. 空状态必须有引导动作——不能只说"暂无数据"，要给用户下一步操作入口
2. 筛选无结果不同于无数据——筛选无结果不给创建按钮，给清除筛选链接
3. 仪表盘数字为 0 不是空状态——¥0.00 是正常数据，只有图表区域才需要占位
4. 公告区无内容直接隐藏——不占空间，比空着更干净

### 7.8 个人中心模块

**功能描述**：成员查看和编辑个人信息、修改密码、退出登录，以及跳转到分类管理和成员管理的入口。在手机端作为底部 TabBar 的"我的"入口；在桌面端通过顶栏头像下拉菜单访问。

**前置条件**：用户已登录。

**页面结构**：

```
┌─────────────────────────────────┐
│          👨  张三               │  ← 头像 + 姓名
│          管理员                  │  ← 角色标签
│          @zhangsan              │  ← 用户名（仅展示）
├─────────────────────────────────┤
│  📒 账单分类                >   │  ← 跳转入口
│  👨‍👩‍👧 家庭成员               >   │  ← 跳转入口
├─────────────────────────────────┤
│  ✏️  修改个人信息                │  ← 弹出编辑表单
│  🔒 修改密码                    │  ← 弹出修改密码表单
│  🚪 退出登录                    │  ← 二次确认后退出
└─────────────────────────────────┘
```

**桌面端入口**：顶栏右侧头像点击，下拉菜单显示"个人信息"、"修改密码"、"退出登录"。分类和成员管理通过侧边栏直接访问，不出现在下拉菜单中。

**手机端入口**：底部 TabBar"我的"标签，进入个人中心页面。分类管理和成员管理作为页面内列表项跳转。

**主流程 — 修改个人信息**：
1. 用户点击「修改个人信息」
2. 弹出表单，预填当前姓名和头像
3. 用户修改姓名（1-20字符）或从预置 emoji 列表重新选择头像
4. 保存后全局同步更新（记账记录者、待办指派人、评论等关联显示）

**主流程 — 修改密码**：
1. 用户点击「修改密码」
2. 弹出表单：旧密码（必填）+ 新密码（必填，6-32字符）+ 确认新密码（必填）
3. 系统校验：旧密码正确、新密码与确认密码一致、新密码不可与旧密码相同
4. 修改成功后清除 Token，跳转登录页重新登录

**主流程 — 退出登录**：
1. 用户点击「退出登录」
2. 弹出二次确认"确定要退出登录吗？"
3. 确认后清除 Token，跳转登录页

**异常流程**：

| 异常场景 | 处理策略 |
|----------|----------|
| 姓名为空或超长 | 前端拦截，提示"请输入1-20字符的姓名" |
| 旧密码错误 | 后端返回错误，提示"原密码错误" |
| 两次新密码不一致 | 前端拦截，提示"两次输入的密码不一致" |
| 新密码与旧密码相同 | 后端返回错误，提示"新密码不能与旧密码相同" |

## 8. 业务规则

| 规则编号 | 规则描述 |

### 8.6 删除规则

| 规则编号 | 规则描述 |
|----------|----------|

| BR-DL09 | 成员禁用规则：有活动记录（在任何模块中产生过数据关联）的成员只能禁用；禁用后无法登录、数据保留、可重新启用；禁止管理员禁用自己 |

### 8.7 并发规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-CC01 | V1 采用 Last Write Wins（最后写入胜出）策略，不引入乐观锁 |
| BR-CC02 | SQLite WAL 模式保证写事务串行化，不会出现数据损坏 |
| BR-CC03 | 写入失败时返回通用错误提示"操作失败，请重试" |

### 8.8 评论规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-CM01 | 评论最多2层嵌套：一级评论（直接评论内容）+ 二级评论（回复一级评论） |
| BR-CM02 | 不允许对二级评论再回复（前端隐藏回复按钮） |

| **安全** | 防暴力破解 | 登录失败5次锁定15分钟 |
| **安全** | 密码复杂度 | 至少包含字母和数字，6-32 字符 |

## 附录 A：术语表

| 术语 | 定义 |
|------|------|
| 管理员(admin) | 系统中拥有全部管理权限的角色，至少一个 |
| 普通成员(member) | 可操作自己内容、查看所有数据的角色 |
| 软删除 | 标记 deleted_at 字段而非物理删除，数据仍保留在数据库中 |
| 硬删除 | ~~已废弃~~ V1 统一采用软删除，不再使用硬删除 |
| 快照 | ~~已废弃~~ V1 早期方案，记账时将分类的收支类型复制到记录上；已改为实时引用分类 type |
| 分 | 金额的最小存储单位，1 元 = 100 分 |
| Token | 认证令牌，登录成功后签发，用于后续请求身份验证 |
| 记录者 | 创建记账记录的用户，与"关联成员"是不同概念 |
| 关联成员 | 记账记录中标注的"这笔开销关联谁"，支持多选（多对多关系），可能与记录者不同 |
| 愿望提升 | 将个人愿望提升为家庭愿望，进入家庭愿望池 |
| 待办变更日志 | 记录待办编辑操作的审计信息（字段、旧值、新值、操作者、时间） |
| 活动记录 | 成员在任何模块（记账/待办/愿望/评论/动态/话题/投票）中产生过的数据关联 |
| 成员禁用 | 将成员标记为不可登录状态，所有关联数据保留，可重新启用 |
| 信息流 | 论坛模块中动态和话题混合按时间倒序展示的列表 |
